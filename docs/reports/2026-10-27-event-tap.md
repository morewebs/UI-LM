# The event tap: volatile masking is live

Date: 2026-10-27. Supersedes the "volatile masking is inert" caveat in the W1
capture report and in the README.

## What was wrong

The rig could tell a real change from a decorative one only when it knew whether
the program had *reported* anything between two frames. Nothing supplied that
fact, so every frame was recorded with `volatile: []`: a spinner tick and a new
tool call were indistinguishable, and no golden set could be built from the
frames without a mask.

## The source

Grok Build keeps an append-only ACP event stream per session:

```
<store>/<bucket>/<session>/updates.jsonl
```

- `<store>` defaults to `~/.grok/sessions`, overridable with `--events`.
- `<bucket>` is the child's working directory with every byte outside
  `[A-Za-z0-9._-]` percent-encoded, so
  `C:\Users\x\AppData\Local\Temp\ui-lm-k5\k5-plain-prompt` becomes
  `C%3A%5CUsers%5Cx%5C...%5Cui-lm-k5%5Ck5-plain-prompt`.
- Each line is a JSON object carrying `timestamp`, `params.update.sessionUpdate`
  and `_meta.agentTimestampMs`.

`crates/capture/src/events.rs` follows that file by its **length**: a longer
stream means the program said something. Length is monotonic, cannot be confused
by a half-written final line, and needs no parsing — which is the next plan's
job when it needs the events' *meaning*.

## The wiring

`frame_from_screen` now takes `event_between` and `acp_event_range`. The record
loop polls the tap before each frame and compares the stream's length with its
length at the previous frame. Three outcomes:

| Tap state | `event_between` | `acp_event_range` |
|---|---|---|
| reached both frames | `now > before` | `Some((before, now))` |
| first frame | `true` (unclassified anyway) | `Some((0, now))` |
| no stream found | **`true`** | `None` |

The last row is the safety property: an unreachable stream means "nobody can
say", and the mask must not read that as "no events happened". `false` would
mark every change the program made of its own accord as noise, which is the
failure the mask exists to prevent. A session recorded without the store is
therefore unchanged from before this work — empty mask, honest frames.

## The evidence

One real recording, 50x160, driven with `say hi in three words` and `/exit`,
`--events` defaulting to the real store. Twelve frames; the recorder was stopped
at the 90 second ceiling before `/exit` landed, which is why the run has no
`session.json` (frames only, the documented killed-capture state).

```
seq 4 row 42: [    \ Waiting for response… 0.5s]    acp_event_range 0 -> 801
seq 5 row 42: [    / Waiting for response… 0.9s]    acp_event_range 801 -> 801
seq 5: 5 volatile spans, first at row 42 col 4, reason no_semantic_change
```

Between frames 4 and 5 the spinner glyph and the elapsed clock changed, the
event stream did not grow (801 801), and the mask named exactly those cells.
Four of the twelve frames carry spans; sixteen cells in total; every one of them
on row 42, the status line the W1 capture report had already identified as the
0.3 s clock. Eight frames carry an event range.

## Labelled frames and real latency

The same tape carries two more facts the frame previously could not state, both added
while there was still one format-change opportunity left:

- **`at_ms`** — milliseconds since the recording loop started. The earlier capture
  could only approximate frame timing by polling the file's length every 100 ms and
  calling the result a lower bound; a real recording now reports it directly
  (`172, 373, 1158, 4727, 6919, 7478`).
- **`event_kinds`** — the `sessionUpdate` labels the application wrote in the stretch
  the frame covers, so a frame says *what happened*, not merely that something did.
  One real recording: frame 4 carries `hook_execution, user_message_chunk` over range
  `0→799`, and the frames after it carry no kinds over `799→799` — the spinner frames
  the mask marks as noise.

Empty `event_kinds` therefore has two meanings, and they are distinguishable: with an
`acp_event_range` it means the application reported nothing in that stretch; with no
range it means no stream was reachable at all.

## What this changes, and what it does not

- **Removed:** the blocking prerequisite for W2's golden set. Screens can now be
  recorded with their decorative noise marked.
- **Unchanged:** the mask is still `no_semantic_change` only; `MaskReason::KnownGlyph`
  remains unreachable, and a glyph-shaped rule would be a second signal rather than
  a replacement for this one.
- **Unchanged:** frames recorded before this work keep `volatile: []`. They are
  not retroactively labelled, and the W1 set should still be re-captured before it
  is used to train anything.
- **Limit:** the tap follows one program's store layout. Recording a different
  application needs its own event source; without one the mask stays empty by
  design rather than guessing.
